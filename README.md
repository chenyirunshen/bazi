# 八字排盘分析系统

一套 **打开就能用** 的四柱八字排盘与分析方法论工具。单文件 HTML，双击即可运行，**不需要安装任何东西，也不需要联网**，计算和渲染全部在本地浏览器完成。

> 既是一个能跑的 App，也是一份装在 App 里的八字教材 —— 九个页签里有一个「理论速查」，把十神表、藏干表、格局顺逆、取用五法、断盘六步都整理好了，边排边查。

---

## 立刻使用

下载 **`八字排盘分析系统.html`**，双击打开。

在线版：<https://chenyirunshen.github.io/bazi/>

输入出生年月日时 + 出生地，点「起盘」即可。

## 三个最容易排错的地方（本系统全部按规矩处理）

**一、换年在立春，不在正月初一。**

八字用的是节气太阳历。2026 年立春是 2 月 4 日 04:02，此前一分钟出生的人年柱仍是 **乙巳** 不是丙午。
这一点和紫微斗数（按农历正月初一换年）完全不同 —— 两个系统的年柱不一样不是 bug，是分界口径不同。

**二、换月只看「节」不看「气」。**

二十四节气里只有十二个「节」才是月份分界：立春·惊蛰·清明·立夏·芒种·小暑·立秋·白露·寒露·立冬·大雪·小寒。
雨水、春分这些「气」只管气候，不管排盘。为此本系统的**节气数据精确到分钟**（寿星万年历算法，覆盖 1900–2100）。

**三、必须换算真太阳时。**

北京时间只是东经 120° 的标准时。

```
真太阳时 = 北京时间 + 经度差（每偏 1° 约 4 分钟）+ 均时差（±16 分钟）
```

乌鲁木齐和北京的经度差近 33°，时差超过 2 小时 —— 不换算，时柱整个就是错的。
另外 **1986–1991 年中国实行过夏令时**，那几年出生的人需要回拨 1 小时（App 里可开关）。

## 流派有分歧的地方，交给你自己选

八字各家算法不统一，本系统不替你「钦定」一派，而是把开关都做出来：

- **晚子时（23:00–24:00）**
  - 古法：日柱不变，时干按「次日日干」起子时
  - 换日法（现代大宗做法）：日柱顺延一天
- **起运折算**
  - 三日折一岁（线性，现代主流）
  - 一时辰折十日（古法）
- **用神定义**：格局派 / 调候派 / 扶抑派各有主张，App 里把三种口径的结论**并列展示**，不作取舍

遇到和别人算得不一样，先对口径 —— 大多数分歧对到这一步就消了。

## 数据可信度

不是「自己跟自己对」，是拿权威实现逐条比对过的：

| 验证项 | 方法 | 结果 |
|---|---|---|
| 四柱干支 | vs lunar-python（寿星万年历移植） | **68 / 68** 完全一致（含两种子时口径） |
| 大运干支 | 男命女命 × 两种起运口径 | **136 / 136** 完全一致 |
| 起运岁数 | 同上 | **136 / 136** 年+月精确匹配 |
| 十神关系 | 10×10 全量 vs 手工核对表 | **100 / 100** |
| 农历互转 | 公历⇄农历往返 + 闰月专项 | **2946 / 2946** |
| UI 交互 | jsdom 全流程冒烟 | **78 / 78**，零运行时错误 |

> 开发过程中踩到过一个值得记的教训：**自洽性检查抓不到系统性错误**。
> 五虎遁公式写错时，自洽测试依然报 34/34 全过 —— 因为它是在拿引擎跟自己对答案。
> 真正把它揪出来的是拿权威实现做交叉验证。**自洽≠正确**，这是排盘类项目特别要当心的一点。

## 开发者用法

```bash
# 改完 src/ 后重新打包
python build.py

# 交叉验证（Node）
node test.js

# UI 测试：测开发版 / 测打包版
node test-ui.js
node test-ui.js dist
```

节气数据与农历数据由 [lunar-python](https://github.com/6tail/lunar-python)（寿星万年历移植）生成，一次生成后静态打包进 App，运行时不再依赖 Python 或网络。
